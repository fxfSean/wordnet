# P0 实现决策

- 项目使用方案列出的 `vocab-pipeline/` 子目录。配置及数据库默认路径相对于当前工作目录。
- 用 `init-state` 验证 SQLite 初始化，用 `mock-response` 检查离线接口。后者接收单条 CandidateSense JSON，输出确定性的 GeneratedSense 占位样本，供本地测试。
- SQLite 使用 `(job_id, record_id)` 作为主键。调用方提供更新时间和状态，每批写入在同一事务中完成。状态推进规则由各流水线阶段实现。
- 20 条开发 fixture 使用合成来源标识，排名留空。测试直接读取 fixture 并构造合成义项，包含词组、连字符、撇号、屈折词形、同形多义输入与一个自造词。它们的真实匹配结果由 P1 验证。

# P1 实现决策

- 每次导入以一份 CSV 更新指定词书的快照。文件内按规范化 lemma 统计重复，完全相同的记录合并，其他来源引用逐条保留。规范化阶段将跨书关联归到同一稳定词条 ID。
- 匹配使用精确 lemma，词组的空格映射为 WordNet 索引中的下划线。自动词形还原暂不启用，`saw` 与 `see` 保持独立。匹配不到的词保留为 `UNMATCHED`。
- 单义项保持 `MATCHED`，多义项进入 `AMBIGUOUS`。所有选中项均来自人工 CSV。同一 lemma 可以有多行，文件内为该 lemma 指定的义项集合替换此前选择，未列出的 lemma 保留其选择。
- 词条的词书关联、许可登记或 WordNet 文件摘要变化时，需要重新匹配和确认受影响的选义。原始输入和配置相同的重跑保留已有选义。
- 以合成数据库验证 WordNet 3.0 文件头、摘要、字节偏移和多词性流程。官方发行包的实测留待下载方式确认后执行。
